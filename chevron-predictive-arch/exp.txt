# Experiment: Minimal Chevron Predictive Architecture vs MLP and Transformer

## Goal

Implement a first local MacBook-scale experiment for Chevron Predictive Architecture, comparing it against a standard MLP and a tiny Transformer on a synthetic sequence prediction task.

The experiment should test whether a fast/slow A/N architecture improves the trade-off between:

1. fast adaptation after hidden rule changes,
2. retention of stable structure through noise or distractors,
3. resistance to A/N collapse or chaotic divergence.

This is not a JEPA experiment. Use ordinary next-token / next-symbol prediction.

## Task

Create a synthetic binary sequence prediction dataset.

The sequence is generated by hidden regimes. Each regime defines a simple rule for predicting the next bit from recent previous bits.

Example regimes:

* `copy`: `x[t+1] = x[t]`
* `not`: `x[t+1] = 1 - x[t]`
* `xor2`: `x[t+1] = x[t] XOR x[t-1]`
* `majority3`: `x[t+1] = majority(x[t], x[t-1], x[t-2])`

The active regime persists for a random duration, for example 50–200 steps, then switches to another regime.

Add optional noise: with probability `p_noise`, flip the generated next bit.

Also add optional distractor bursts: for 5–10 steps, replace the rule output with random bits, then return to the same regime.

The model observes only the bit sequence. It is not given the regime label.

Input: fixed context window of previous bits, e.g. 32 or 64 bits.
Target: next bit.

## Models

Implement and compare three models with roughly similar parameter counts.

### 1. MLP baseline

A simple feedforward network.

Input shape:

```python
batch_size x context_length
```

Architecture:

```python
Linear(context_length, hidden_dim)
GELU
Linear(hidden_dim, hidden_dim)
GELU
Linear(hidden_dim, 2)
```

Output: logits for next bit.

### 2. Tiny Transformer baseline

A small causal Transformer encoder/predictor.

Suggested configuration:

```python
context_length = 64
d_model = 32 or 64
num_layers = 2
num_heads = 2 or 4
```

Use token embeddings for bits plus positional embeddings. Predict next bit from the final token representation.

Output: logits for next bit.

### 3. Minimal Chevron Predictive Architecture

Implement a recurrent CPA model with two hidden states:

```python
A = fast adaptive proposal state
N = slow retained constraint state
```

At each input bit `x_t`, embed the bit and update A and N.

Suggested update:

```python
A_update = W_AA(A) + W_AN(N) + W_xA(x_embed)
N_update = W_NA(A.detach()) + W_NN(N) + W_xN(x_embed)

A_next = LayerNorm(A + GELU(A_update))
N_candidate = LayerNorm(N + GELU(N_update))

N_next = (1 - rho) * N + rho * N_candidate
```

Use a small `rho`, e.g.:

```python
rho = 0.01, 0.05, or 0.10
```

Prediction should use both channels and their relation:

```python
features = concat(A, N, A - N, A * N)
logits = prediction_head(features)
```

Prediction head:

```python
Linear(4 * hidden_dim, hidden_dim)
GELU
Linear(hidden_dim, 2)
```

The CPA model should process the full context window recurrently and predict the next bit from the final A/N state.

## Loss

All models use cross-entropy prediction loss:

```python
loss_pred = cross_entropy(logits, target)
```

For CPA, add two optional regularizers.

### A/N distance-band regularizer

Prevent collapse while also avoiding uncontrolled divergence.

```python
dist = mean((A - N) ** 2)
loss_band = (dist - target_dist) ** 2
```

Suggested:

```python
target_dist = 1.0
lambda_band = 0.01
```

### Slow-N regularizer

Encourage N to move slowly.

```python
loss_slow = mean((N_next - N_prev) ** 2)
```

Suggested:

```python
lambda_slow = 0.001
```

Total CPA loss:

```python
loss = loss_pred + lambda_band * loss_band + lambda_slow * loss_slow
```

Make these regularizers configurable.

## Evaluation Metrics

Report the following metrics for all models.

### 1. Overall next-bit accuracy

Standard test accuracy across all test sequences.

### 2. Post-switch recovery time

After a hidden regime switch, measure how many steps it takes before rolling accuracy returns above a threshold, e.g. 80%.

Report average recovery time.

### 3. Noise resistance

Evaluate at different noise levels:

```python
p_noise = 0.0, 0.05, 0.10, 0.20
```

Report accuracy degradation.

### 4. Distractor resistance

During short random distractor bursts, measure:

* accuracy during distractor,
* accuracy immediately after distractor,
* number of steps needed to recover.

The CPA hypothesis is that A may wobble during distractors, but N should retain useful structure.

### 5. CPA diagnostics

For the CPA model only, log:

```python
mean_squared_distance(A, N)
cosine_similarity(A, N)
mean_squared_change(N_t, N_t_minus_1)
mean_squared_change(A_t, A_t_minus_1)
```

Plot these over time, especially around regime switches and distractor bursts.

## Expected Result

CPA does not need to win on raw accuracy alone.

A promising result would be that CPA shows a better trade-off between:

* fast adaptation after genuine regime switches,
* slower overreaction to temporary noise,
* stable but non-collapsed A/N separation.

In other words, the key success criterion is not simply:

```text
highest accuracy
```

but:

```text
better adaptation-retention trade-off than MLP and tiny Transformer
```

## Interpretation

If CPA collapses, A and N become too similar and the architecture is not using retained difference.

If CPA diverges, A and N become unrelated and prediction should degrade.

The interesting regime is between these failures: A and N remain distinct but coupled.

The experiment should therefore treat A/N separation as a first-class measurement, not merely an internal implementation detail.
